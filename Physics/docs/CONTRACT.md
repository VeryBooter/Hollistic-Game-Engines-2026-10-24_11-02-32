# 数据交换协议 v1

机器约束在 `schema/state.schema.json`，运行时在输入和输出边界验证，并拒绝 NaN/Infinity。
缺失字段代表该求解器没有提供，不能解释成零。禁止将未解析的命令行输出当成物理状态。

- 单位：SI；长度 m、速度 m/s、时间 s、质量 kg、力 N、力矩 N·m、温度 K、压力 Pa、惯量 kg·m²。
- 世界坐标：右手 NED，X 北、Y 东、Z 下。`position_m` 是某个场景固定局部原点的坐标；跨场景必须另行约定同一个地理原点。JSBSim 示例仅输出 ASL 高度和 NED 速度，没有伪造局部位置。
- 机体坐标：右手 BODY_FRD，X 前、Y 右、Z 下。载荷必须携带 frame，质量中心和惯量以机体坐标表示。惯量关于质心；质量中心的位置以约定机体原点为参考。真实接入需统一该原点。
- `time_s` 为仿真开始后的时间，`step_s` 为实际推进步长。静态分析二者可为零。流水线要求输入时间严格递增，保持源时间戳；目前不插值、不重采样、不实现反馈迭代。
- `geometry.revision` 是递增的几何修订号；`mesh_uri` 标识基础网格，`vertex_ids` 与 `displacements_m` 一一对应，是相对基础网格的位移。更换拓扑必须发布新的基础网格 URI 和修订号。字段存在性、长度、唯一 ID 由 host 校验；跨帧修订策略仍由调用方管理。
- 惯量矩阵必须是对称半正定的 3×3 张量。单独力矩不能推断其施加点；载荷搬移到不同原点时调用方须加入 r×F。

JSBSim 边界转换：ft×0.3048、Rankine×5/9、psf×47.88025898033584、lbf×4.4482216152605、lbf·ft×1.3558179483314、slug×14.5939029372。具体属性读取见 `physim/adapters.py`。当前 C172 示例为短暂的未配平自由响应，只验证接入，不表示经验证的飞行工况或控制器。

Unity 采用 X 右、Y 上、Z 前。世界极向量变换 `(N,E,D) -> (E,-D,N)`；该矩阵行列式为 -1，所以力矩和角速度等轴向量必须用 `det(R) R`，即 `(-E,D,-N)`。机体载荷应先使用机体姿态变换到 NED，再应用上述世界变换。不可直接把 BODY_FRD 当 NED。张量按 `R I Rᵀ` 变换；四元数转换尚未实现。

`unity/PhysicsExchange.cs` 是可独立编译的 DTO/坐标转换预留接口，未加入 Assets，也未接入 Unity Play Mode。基础 DTO 不是完整 schema：嵌套惯量数组和几何更新应使用支持这些结构的 JSON 库。当前传输方式为主进程调用 CLI，JSON 文件交接。后续若加入持久进程、socket 或 C ABI，应继续遵守此协议。

调度：`modules.json` 注册模式与启用状态；Host 在独立进程启动求解器，设置超时，正常结束回收，异常时终止整个进程组。`Host.stop()` 可由监督线程调用。一个 Host 同时管理一个作业，pipeline 按依赖顺序运行，不能前向引用；离线程序由相同入口管理。`realtime_candidate` 只表示候选用途，当前进程/JSON 作业机制没有硬实时延迟承诺。
